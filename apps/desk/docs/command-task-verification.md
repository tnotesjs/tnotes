# Desk 命令任务与底部终端面板联动 · 验证报告

本轮范围：手动 Git 操作（fetch / 拉取 / 推送）与 IDE 启动器的**执行过程**接入底部面板，
作为底部面板中的「命令任务标签」，与交互式 Shell 会话并列。

## 一、结论

**macOS 已测范围通过。** 已实测项见第三节（共 **24 项**，全部通过）；
未验证项见第四节（**7 项**，不计入通过）。取消与超时是本轮核心交付，其中

## 二、排查中定位并修复的真实缺陷

E2E 一度完全打不通（任务停在「已排队」），逐段定位后确认是**四个独立缺陷叠加**，
都不是猜测出来的，而是用「同一 taskId/run 的双侧探针」逐一定位的：

| #   | 缺陷                                   | 现象                                                                                | 定位证据                                                        | 修复                                                                                      |
| --- | -------------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 1   | **IPC 返回了带方法的对象**             | 合法 payload 反而报 `An object could not be cloned.`（校验失败的 payload 却"正常"） | 二分：字面量合法 payload THROW、`cwd: ''` 返回校验错误          | `command-task:claim` 改为返回纯 `CommandTaskDto`；新增 `claimHandle()` 供进程内取执行句柄 |
| 2   | **`claim` 复用运行中任务时自增 `run`** | 渲染端 `run=1`、主进程 `run=2`，阶段上报被当"旧运行"丢弃                            | 任务列表显示 `run: 2`                                           | 只有**开始新一轮运行**才自增                                                              |
| 3   | **`extras` 在入队时被固化**            | 实时输出与取消信号全部丢失                                                          | 探针 `enqueue.merged hasSignal=false` 早于 `runGitTask.options` | `enqueue` 的 extras 支持**工厂函数**，执行时才求值                                        |
| 4   | **取消不去终止占住队列的操作**         | 点「停止」15 秒仍 `running`                                                         | 探针显示是**后台定时 fetch 先占住队列**，手动任务在排队         | 取消时先 `abortActiveOperation(kb)` 终止占队列的操作                                      |

另外修掉两个通用缺陷：

- **`zod` 错误响应不可克隆**：issue 里带着 schema 实例（含 `RegExp`），
  `handle()` 的 `INVALID_REQUEST` 路径会把 IPC 变成克隆错误。改为只回传纯数据。
- **退出应用不终止 git 子进程**：`gitManager.dispose()` 只等队列收敛，一个挂住的
  `git fetch` 会把退出流程一起拖住并留下孤儿。新增按知识库登记的在跑操作终止器，
  `dispose()` 先终止再等收敛。

## 六、排查方法（供后续复用）

- **固定被测产物**：`rm -rf apps/desk/out` → 构建 → 记录 `main` 的 sha256 与 renderer 入口文件名；
  用 `grep -l "<明确字符串>" out/**/*.js` 确认标记确实在产物里。**不要**在构建中间态观察产物
  （我因此在错误结论上绕了很久）。
- **双侧同源探针**：临时加一条 `DESK_PROBE_FILE` 环境变量门控的探针通道，渲染端与主进程
  写同一个文件、带 `taskId/run`，一次运行即可看清链路断在哪一段。
- **禁止**在页面里 monkey-patch `window.desk.*`：`contextBridge` 暴露的对象是冻结的。
- 主进程 stdout 在 GUI 模式下不可靠，**用文件**。
- 页面异常要用 `page.on('pageerror')` + `page.on('console')` 双通道捕获。
