## 二、代码复核后修复的问题

复核提出的 5 个问题 + 3 项收尾，逐一修复并补测试：

| 编号   | 问题                                                                                                     | 修复                                                                                                                                                                                        |
| ------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1-1   | 进程退出后 `TerminalPane` 被 `v-else` 卸载，xterm 与回滚缓冲一起销毁，而提示写着「输出已保留」           | 退出**不再卸载**终端实例，改为在下方叠一条退出提示条（含退出码/信号）；重启前先清屏，避免新提示符接在旧内容后面                                                                             |
| P1-2   | 消费者未注册时输出被直接丢弃，字节却仍计入未确认量，累积后会永久暂停；恢复列表里的非激活会话也没有消费者 | store 增加**按会话的有界缓冲**（上限 4MB，溢出丢最旧并计数），`registerHandler` 时按序回放、字节照常回执；`TerminalPane` 改为**所有会话都挂载**（非激活会话也有消费者）；关闭会话时清理缓冲 |
| P2-3   | 水位只算 `unacked`，`pendingBytes` 不参与，512KB 不是整条链路上限                                        | 背压改为按 **`pending + unacked`** 判定；`paused` 标志避免重复 pause/resume；新增 `backpressureSnapshot()` 便于观测与测试                                                                   |
| P2-4   | `cwd` 只用字符串前缀比较：`/库根/../别处` 能过，Windows 路径未处理，软链未解析                           | 改为 `realpathSync` + `statSync` + `path.relative` 判定：**规范化、真实路径（解析软链）、必须是已存在目录**；注释改成「限制**初始**工作目录」，并写明 shell 起来后可以自行 `cd`             |
| P2-5   | 单次写入限 64K 字符，`TerminalPane` 直接发整段 `onData` 且忽略错误 → 大段粘贴被静默拒绝                  | 渲染端**按码点分片**（32K 字符）的串行写队列：按序发送、失败用 toast 明确提示；分片不会在代理对/组合字符中间断开                                                                            |
| 收尾-1 | Shell 探测只查存在性，与注释不符                                                                         | 改用 `accessSync(X_OK)`；补测试「不可执行的文件不能当 shell」                                                                                                                               |
| 收尾-2 | 终端单测只覆盖 shell 与环境变量                                                                          | 扩到 **25 条**：会话生命周期（创建/退出/异常退出/重启/重命名/关闭/dispose/resize/写入/重名）+ 流控（高吞吐暂停恢复、慢消费者、合批不丢、退出前冲刷）；另新增 `resolveInitialCwd` **8 条**   |
| 收尾-3 | 文档阶段划分与清单数字不准                                                                               | 本文件重写：阶段划分见上表，逐节列证据，数字与列项对齐                                                                                                                                      |

修复过程中另外发现并修掉两个**真实缺陷**（由新测试暴露）：

- **重启会把用户重命名过的标签覆盖回 `bash`**：spawn 时无条件用 shell 名当标题，现在只有首次创建才这么做；
- **`TERM=dumb` 被视为有效值**：Finder 启动的打包应用、部分 CI 会带 `TERM=dumb`，会让颜色与 TUI 直接降级；现在把它当「不可用值」升级为 `xterm-256color`（用户显式设置的其他 TERM 仍不动）。

## 四、未验证项（**不计入通过**，明确不宣称支持）

| 项                       | 状态                                                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **真实输入法（IME）**    | **未验证**。真实 IME 的合成事件在 Electron 里不可靠（合成 `compositionend` 不进入 xterm 的输入路径）。已验证的是「中文经键盘事件送达并作为参数执行」（#47/#48），**不等于真实输入法可用**，需人工用系统输入法敲一次 |
| **真实 Finder 双击启动** | **未验证**。阶段 0 用 `env -i` 最小环境近似 PATH 结论；打包态验收是命令行启动 .app，不是 LaunchServices 双击                                                                                                        |
| Windows 10/11            | **未验证**。ConPTY/winpty 行为未测；包内预构建为 `win32-*`，编译需 Spectre-mitigated 库                                                                                                                             |
| Linux（x64/arm64）       | **未验证**。包内无 `linux-*` 预构建，安装会走 node-gyp 编译，工具链未确认                                                                                                                                           |
| 极慢消费者下的丢弃行为   | 缓冲**溢出丢弃分支**只做了单测（4MB 上限），没有在真实慢渲染端上跑到溢出                                                                                                                                            |
