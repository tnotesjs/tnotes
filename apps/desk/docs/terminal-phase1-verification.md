# Desk 终端 · 阶段 1 验收报告

阶段 1 的范围是「独立底部面板 + 真实 shell + 多会话 + 目录归属 + 会话生命周期」，
外加第一版表格里的阅读与输入项（复制粘贴、清屏、输出搜索、字号、主题跟随）。
阶段 2（分屏、Shell 配置、收藏命令、代码块发送到终端、路径跳转、AI CLI 集成）不在本阶段。

## 一、结论

第一版功能已实现并通过端到端验收。核心不变量（目录归属、文件变更不覆盖未保存笔记、
收起 ≠ 结束进程）都有实测证据。

## 二、已定并实现的行为

| 项       | 实现                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 面板形态 | 独立底部面板，不扩展 `EditorTab`、不接入 `EditorLayoutNode`；支持拖动高度、收起、最大化                       |
| 快捷键   | `Cmd/Ctrl+J` 开关（展开时无会话则自动新建并聚焦）；面板聚焦时内部先接管并阻止冒泡，避免与窗口级处理器互相抵消 |
| 入口     | 标题栏按钮（带运行中数量提示）+ 命令面板「切换终端面板」                                                      |
| Shell    | 自动探测：`$SHELL`（有效才用）→ zsh → bash → sh；Windows 走 PowerShell、`cmd.exe` 兜底。配置项留第二版        |
| 环境     | 继承并补全：只补 `TERM`/`COLORTERM`/`LANG`，**不覆盖**已有值、**不手工拼 PATH**（登录 shell 自己解析）        |
| 输出搜索 | `Cmd/Ctrl+F` 查找条；Enter 下一个 / Shift+Enter 上一个 / Esc 关闭；中英文均可命中                             |
| 字号     | `Cmd/Ctrl+=` / `-` / `0`，范围 8–24px，存 localStorage                                                        |
| 主题     | 跟随 `document.documentElement` 的 `data-theme`，切换主题时终端配色同步更新                                   |
| 流控     | 输出 16ms 合批；按未回执字节在 512KB/128KB 高低水位之间 `pause`/`resume` PTY                                  |
| 退出清理 | 按**进程组**结束会话（只 kill shell 会把 `vite dev`、`sleep &` 之类留成孤儿）                                 |

### 3.3 文件变更与该有的冲突处理（5/5）

| 场景                              | 结果                                                                                                  |
| --------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 窗口缩放后终端列数跟随            | ✅ `stty size` 实测 204 → 143                                                                         |
| 未编辑文档被终端改写 → 编辑器刷新 | ✅ 显示终端写入的新内容                                                                               |
| 有未保存内容时终端改写同一文件    | ✅ **保住用户编辑**（`未保存的编辑XYZ` 仍在，终端内容未进编辑器）                                     |
| 冲突提示入口                      | ✅ 出现 `.conflict-banner`：「磁盘内容已经变化，Desk 没有覆盖你的编辑。」+「载入磁盘 / 保留编辑内容」 |

**关于"终端不受写入门禁约束"**：终端里跑脚本或 `git checkout` 直接改磁盘，Desk 的
写入门禁完全不参与（门禁只约束 Desk 自己的写入路径）。因此这里的保护来自**文件监听 +
未保存冲突判定**，而不是门禁。为此补了两条主进程回归测试（`scan.test.ts`）：

- 终端直接改笔记 → 必须发出 `noteExternalChanged`（不能因为"没有门禁记录"被忽略）；
- Desk 自己刚写过的路径仍被忽略（内部写入不当作外部变更）。
