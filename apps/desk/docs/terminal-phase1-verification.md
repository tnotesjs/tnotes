### 复核之外发现的进程级缺陷（P0）

**现象**：`DiagnosticReports` 里出现一份 `TNotes Desk-...225006.ips`。崩溃栈为
`pty.node → Napi::ThreadSafeFunction::CallJS → __cxa_throw → abort`
（EXC_CRASH / SIGABRT）。根因是 **node-pty 的线程安全函数不捕获宿主回调抛出的异常**，
而窗口销毁时 `webContents.send` 正好会抛——终端输出还在飞的时候关闭应用就会命中。

**修法**：三处建立防线——注册给 node-pty 的 `onData`/`onExit` 回调统一包一层 guard，
状态推送 `emit()` 与数据推送 `safeSendData()` 各自 try/catch，异常只记日志、绝不向上抛。

**证据边界（不夸大归因）**：

| 证据                       | 值                                                         | 说明                                                                                           |
| -------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `procPath`                 | `/Users/USER/*/TNotes Desk.app/Contents/MacOS/TNotes Desk` | 真实路径落在用户目录，**不是** `/Applications`                                                 |
| `parentProc` / `parentPid` | `node` / 43272                                             | 说明由 Node 启动（Playwright 就是这样拉起 app 的），但**单凭这一项不能确认是哪个会话**         |
| `procLaunch` → 崩溃        | 22:49:46 → 22:50:06                                        | 与当时正在跑的打包态 e2e 时间线吻合                                                            |
| 报告记录的退出             | `SIGNAL 6 / Abort trap: 6`                                 | 报告里只有 `termination`，**没有捕获到 stderr**                                                |
| 崩溃栈                     | `pty.node` 的 N-API 回调                                   | 该安装版 **不含** `terminal:create` 与 `node-pty`（已核对），因此不可能是 `/Applications` 那份 |

结论：可确认"由 Node 启动的某个打包实例"，**不能**确认是哪一个具体会话，所以不做回移。

**验证**：用「关闭应用时终端仍在高速输出」复现测试，前后崩溃报告数 **1 → 1**（辅助证据，
不是充分证据）；另有 3 条单测锁定该防线（数据监听器抛、状态监听器抛、订阅方只抛一次）。

### 由新测试暴露的两个真实缺陷

- **重启会把用户重命名过的标签覆盖回 `bash`**：spawn 时无条件用 shell 名当标题，现在只有首次创建才这么做；
- **`TERM=dumb` 被视为有效值**：Finder 启动的打包应用、部分 CI 会带 `TERM=dumb`，会让颜色与 TUI 直接降级；现在把它当「不可用值」升级为 `xterm-256color`（用户显式设置的其他 TERM 仍不动）。
